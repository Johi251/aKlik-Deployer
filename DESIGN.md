# aKlik-Deployer design system

## Direction
Operate mode. A quiet personal deployment console. The current explicit brief replaces the earlier daylight/red presentation. Start with one repository composer and real recent checks; keep the existing explanatory chapters below it. No artificial metrics or fabricated project statuses.

## Surfaces and typography
Manrope is served locally. Near-black canvas, slightly raised working panels, 1px neutral borders and restrained corner radii. Use cobalt on primary actions with white text; use a lighter blue for text links and focus rings so dark-background contrast remains readable. Operational body copy is 14px, metadata at least 12px. Green, blue and orange are semantic status indicators, always accompanied by words.

## Signature interaction
Submit one repository URL to reach the analysis. The form preserves keyboard submission and visible labels. Recent checks reopen the actual stored report. The explanatory workflow seeks with the scroll position; reduced-motion users receive static scene states. Blur is limited to the header. The fine grid belongs only to the repository analysis canvas.

## Layout
246px sidebar on wide screens, collapsed menu below 1000px. The repository input wraps above the submit button below 600px. Recent checks and the status key split at wide widths and stack on smaller screens. The application, error, loading, offline and empty states use the same dark surfaces.

## Verification
Rendered with Edge at 1440×960 and 390×844. Browser captures recorded no page errors. Static and interaction checks are evidence of implementation, not a claim of external user approval. Bookmarks Manager retains its separately maintained orange identity; only its aKlik integration is changed.
